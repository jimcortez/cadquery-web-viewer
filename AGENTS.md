# AGENTS.md

Guidance for AI coding agents working in **cadquery-web-viewer** (CadQuery Web Viewer).

## What this project is

A **hard fork** of [Yet Another CAD Viewer (YACV)](https://github.com/yeicor-3d/yet-another-cad-viewer): a browser-based 3D viewer for **GLB / glTF 2.0** meshes with a Python backend for tessellation, live updates over SSE, and static export. It targets a **mostly drop-in replacement** for YACV’s Python API and HTTP contract, with renamed packages and explicit `server_type` modes.

Primary user flow: Python calls `show()` on CadQuery, build123d, or raw GLB bytes → tessellation → versioned object store → SSE notifies the UI → the page fetches GLBs and renders with [model-viewer](https://modelviewer.dev/) plus Three.js tooling.

| Path | Role |

| `examples/in-process/`, `examples/remote/` | Sample `show()` usage |
| `tests/` | Python `unittest` tests (Flask test client) |
| `assets/licenses.txt` | Third-party JS licenses (regenerated by `yarn update-licenses` during build) |
| `.agents/skills/` | Optional agent skills (Vue, README, composables, etc.) |

## Architecture (data flow)

```text
Python show() / CLI
    → tessellate (build123d / OCP) → GLB bytes
    → PUT /api/object/<name>  (store version; no UI update yet)
    → POST /api/events        (object.created | object.versioned | …)
    → GET /api/events         (SSE to browser)
    → GET /api/object/<name>  (browser downloads GLB)
    → model-viewer + @gltf-transform in the UI
```

**Important split:** storing a GLB (`PUT /api/object`) does **not** update the viewer; publishing an SSE event (`POST /api/events`) does. See [docs/api.md](docs/api.md).

### Python modules (high level)

| Module | Responsibility |
|--------|----------------|
| `__init__.py` | Public API: `show`, `show_all`, `remove`, `clear`, `render`, `export_all`, `viewer` singleton |
| `engine.py` | `CadQueryWebViewer`: tessellation pipeline, scene state, publish to pub/sub |
| `app.py` | Flask routes: static UI, `/api/object`, `/api/events`, CORS |
| `object_store.py` | Versioned in-memory (and optional disk) GLB storage |
| `events_api.py` | SSE event types and validation |
| `pubsub.py` | Buffered pub/sub for SSE subscribers |
| `tessellate.py`, `gltf.py`, `cad.py` | CAD → mesh → GLB |
| `http_client.py` | Remote `server_type="remote"` client |
| `embedded_server.py` | In-process Flask thread for default `show()` |
| `glb_cache.py` | Optional on-disk GLB cache for long-lived server |
| `url_import.py` | Fetch GLB from URL on JSON `PUT /api/object` |
| `cli.py` | `cadquery-web-viewer` entry point |

### Frontend structure

- **Framework:** Vue 3 Composition API (`<script setup>`), Vuetify 4, TypeScript.
- **3D:** `@google/model-viewer`, `three` (must be **deduped** with model-viewer in Vite — see `vite.config.ts` `resolve.dedupe`).
- **GLB editing:** `@gltf-transform/*` via `sceneDocument` in `App.vue`.
- **Live updates:** `frontend/misc/network.ts` (`NetworkManager`) subscribes to SSE and batches UI updates.
- **Composables:** `frontend/composables/` (e.g. `useAppModelLoading`, `useObjectPicker`, `useGltfFileDrop`).
- **Alias:** `@/` → `frontend/` (Vite).

For Vue work, prefer skills under `.agents/skills/` (especially `vue-best-practices`, `create-adaptable-composable`, `vue-testing-best-practices`).

## Development setup

**Requirements:** Python **3.10–3.12** (`requires-python` in `pyproject.toml`), Node.js + Yarn for the UI.

```bash
uv sync                    # or: pip install -e ".[dev]"
yarn install               # full install; needed for yarn build (not production-only)
```

**Two terminals (typical UI work):**

```bash
# Terminal 1 — Flask API (default http://localhost:32323)
uv run cadquery-web-viewer

# Terminal 2 — Vite dev server (often http://localhost:5173)
yarn dev
```

Vite dev proxies API calls: same-origin `/api/events` when possible; otherwise falls back to `http://localhost:32323`. Details: [docs/development.md](docs/development.md).

**Backend-only** (serving a built UI):

```bash
yarn build                 # writes repo-root dist/
uv run cadquery-web-viewer # serves dist/ if packaged frontend/ is absent
```

Do **not** set `NODE_ENV=production` for `yarn install` before `yarn build` — devDependencies (e.g. `generate-license-file`) are required.

## Commands agents should know

| Task | Command |
|------|---------|
| Run API server | `uv run cadquery-web-viewer` or `python -m cadquery_web_viewer` |
| Frontend dev | `yarn dev` |
| Production UI build | `yarn build` (runs license update, `vue-tsc`, Vite) |
| Python lint | `uv run ruff check cadquery_web_viewer hatch_build.py` |
| Python typecheck | `uv run pyright` |
| Python tests | `uv run python -m unittest discover -s tests -v` |
| Wheel build (CI style, skip UI build) | `CADQUERY_WEB_VIEWER_SKIP_FRONTEND_BUILD=true uv build` |

CI (`.github/workflows/ci.yml`) runs the reusable build: `yarn build`, `uv build` with skip flag, and Docker image validation.

## Coding conventions

### Python

- Target **3.10+** syntax; line length **120** (Ruff).
- Ruff selects: `E4`, `E7`, `E9`, `F`, `I` — run before submitting changes.
- Pyright is configured with relaxed reporting in `pyproject.toml`; still match existing types and patterns in `cadquery_web_viewer/`.
- **Runtime dependency:** `build123d` (tessellation). **CadQuery** is *not* a package dependency; users install it separately for CadQuery examples.
- Prefer extending `CadQueryWebViewer` / Flask blueprints in `app.py` rather than duplicating store or event logic.

### TypeScript / Vue

- Use **Composition API** with `<script setup lang="ts">`.
- Put reusable logic in `frontend/composables/`; keep components focused.
- `model-viewer` is a **custom element** (configured in `vite.config.ts`).
- After changing `package.json` dependencies, `yarn build` refreshes `assets/licenses.txt` — commit that file when deps change.

### Scope and style for agents

- **Only change code required for the task.** No drive-by refactors or unsolicited markdown/docs.
- **Do not create git commits** unless the user explicitly asks.
- Match existing naming, imports, and error-handling patterns in the file you edit.
- When touching the HTTP API, update [docs/api.md](docs/api.md) if behavior or contracts change.
- Preserve **YACV migration** semantics documented in [docs/yacv_migration.md](docs/yacv_migration.md) unless the task is explicitly to break compatibility.

## `show()` and server modes

| `server_type` | Behavior |
|---------------|----------|
| `"in-process"` (default) | Starts embedded Flask, publishes models, optionally blocks until viewer disconnects |
| `"remote"` | HTTP client to an already-running `cadquery-web-viewer` (`remote_options`) |
| `"local"` | In-memory buffer only; no browser server |

Public helpers: `show`, `show_all`, `remove`, `clear`, `render`, `export_all`. See [docs/usage.md](docs/usage.md).

## Environment variables

| Variable | Effect |
|----------|--------|
| `FRONTEND_BASE_PATH` | Override directory for static UI (default: `cadquery_web_viewer/frontend`, else repo `dist/`) |
| `CADQUERY_WEB_VIEWER_SKIP_FRONTEND_BUILD` | Skip Vite during `uv build` / hatch hook |
| `CADQUERY_WEB_VIEWER_SMALL_BUILD` | Smaller wheel frontend build (excludes some large Three assets) |
| `VITE_BASE` | Vite `base` for subdirectory deploys |

## Packaging

- Build backend: **Hatchling** + custom hook in `hatch_build.py` (runs `yarn build` into `cadquery_web_viewer/frontend` unless skipped or prebuilt).
- Wheel includes prebuilt `cadquery_web_viewer/frontend` when present.
- Version is mirrored in `pyproject.toml` and `package.json`.

## Testing

- Tests live in `tests/` and use **`unittest`** (stdlib), not pytest.
- Pattern: `create_app(cache_mode="memory")` + Flask `test_client()`; mock external HTTP with `unittest.mock.patch`.
- Add tests for new `/api/*` behavior, especially validation and status codes documented in [docs/api.md](docs/api.md).

## Common pitfalls

1. **Forgetting the two-step remote workflow** — `PUT` then `POST /api/events`.
2. **Editing `cadquery_web_viewer/frontend/` directly** — change `frontend/` and run `yarn build`.
3. **Breaking Three.js sharing** — do not add a second unresolved `three` copy; keep Vite `dedupe`.
4. **Assuming CadQuery is installed** — examples may use `cadquery`; the library depends on `build123d`.
5. **Python 3.13+** — not supported (`requires-python` caps at 3.12).
