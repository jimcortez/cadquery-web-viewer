# AGENTS.md

Guidance for AI coding agents working in **cadquery-web-viewer** (CadQuery Web Viewer).

> **Looking for the human dev setup, commands, and coding conventions?** See
> [CONTRIBUTING.md](CONTRIBUTING.md). This file focuses on the project model
> and rules that are easy for an agent to miss.

## What this project is

A **hard fork** of [Yet Another CAD Viewer (YACV)](https://github.com/yeicor-3d/yet-another-cad-viewer):
a browser-based 3D viewer for **GLB / glTF 2.0** meshes with a Python backend
for tessellation, live updates over SSE, and static export. It targets a
**mostly drop-in replacement** for YACV's Python API and HTTP contract, with
renamed packages and explicit `server_type` modes.

Primary user flow: Python calls `show()` on CadQuery, build123d, or raw GLB
bytes → tessellation → versioned object store → SSE notifies the UI → the page
fetches GLBs and renders with [model-viewer](https://modelviewer.dev/) plus
Three.js tooling.

## Repository layout

The full layout is in [CONTRIBUTING.md](CONTRIBUTING.md#project-layout). Two
splits an agent must respect:

- **Frontend source** lives in `frontend/`. The **built bundle** lives in
  `cadquery_web_viewer/frontend/` and is regenerated by `yarn build`. **Do not
  edit `cadquery_web_viewer/frontend/` by hand.**
- **`build123d` is a runtime dependency. `cadquery` is not** — examples may
  import `cadquery`, but the package itself targets build123d for tessellation.

## Architecture (data flow)

```text
Python show() / CLI
    → tessellate (build123d / OCP) → GLB bytes
    → PUT /api/object/<name>  (store version; no UI update yet)
    → POST /api/events        (object.created | object.versioned | …)
    → GET /api/events         (SSE to browser)
    → GET /api/object/<name>  (browser downloads GLB)
    → model-viewer + @gltf-transform in the UI
```

**Important split:** storing a GLB (`PUT /api/object`) does **not** update the
viewer; publishing an SSE event (`POST /api/events`) does. See
[docs/api.md](docs/api.md).

### Python modules (high level)

| Module | Responsibility |
|--------|----------------|
| `__init__.py` | Public API: `show`, `show_all`, `remove`, `clear`, `render`, `export_all`, `viewer` singleton |
| `engine.py` | `CadQueryWebViewer`: tessellation pipeline, scene state, publish to pub/sub |
| `app.py` | Flask routes: static UI, `/api/object`, `/api/events`, CORS |
| `object_store.py` | Versioned in-memory (and optional disk) GLB storage |
| `events_api.py` | SSE event types and validation |
| `pubsub.py` | Buffered pub/sub for SSE subscribers |
| `tessellate.py`, `gltf.py`, `cad.py` | CAD → mesh → GLB |
| `http_client.py` | Remote `server_type="remote"` client |
| `embedded_server.py` | In-process Flask thread for default `show()` |
| `glb_cache.py` | Optional on-disk GLB cache for long-lived server |
| `url_import.py` | Fetch GLB from URL on JSON `PUT /api/object` |
| `cli.py` | `cadquery-web-viewer` entry point |

### Frontend structure

- **Framework:** Vue 3 Composition API (`<script setup>`), Vuetify 4, TypeScript.
- **3D:** `@google/model-viewer`, `three` (must be **deduped** with model-viewer
  in Vite — see `vite.config.ts` `resolve.dedupe`).
- **GLB editing:** `@gltf-transform/*` via `sceneDocument` in `App.vue`.
- **Live updates:** `frontend/misc/network.ts` (`NetworkManager`) subscribes to
  SSE and batches UI updates.
- **Composables:** `frontend/composables/`.
- **Alias:** `@/` → `frontend/` (Vite).

For Vue work, prefer skills under `.agents/skills/` (especially
`vue-best-practices`, `create-adaptable-composable`,
`vue-testing-best-practices`).

## Scope and style for agents

- **Only change code required for the task.** No drive-by refactors or
  unsolicited markdown/docs.
- **Do not create git commits** unless the user explicitly asks.
- Match existing naming, imports, and error-handling patterns in the file you
  edit.
- When touching the HTTP API, update [docs/api.md](docs/api.md) if behavior or
  contracts change.
- Preserve **YACV migration** semantics documented in
  [docs/yacv_migration.md](docs/yacv_migration.md) unless the task is explicitly
  to break compatibility.

## `show()` and server modes

| `server_type` | Behavior |
|---------------|----------|
| `"in-process"` (default) | Starts embedded Flask, publishes models, optionally blocks until viewer disconnects |
| `"remote"` | HTTP client to an already-running `cadquery-web-viewer` (`remote_options`) |
| `"local"` | In-memory buffer only; no browser server |

Public helpers: `show`, `show_all`, `remove`, `clear`, `render`, `export_all`.
See [docs/usage.md](docs/usage.md).

## Environment variables

| Variable | Effect |
|----------|--------|
| `FRONTEND_BASE_PATH` | Override directory for static UI (default: `cadquery_web_viewer/frontend`, else repo `dist/`) |
| `CADQUERY_WEB_VIEWER_SKIP_FRONTEND_BUILD` | Skip Vite during `uv build` / hatch hook |
| `CADQUERY_WEB_VIEWER_SMALL_BUILD` | Smaller wheel frontend build (excludes some large Three assets) |
| `VITE_BASE` | Vite `base` for subdirectory deploys |

## Packaging

- Build backend: **Hatchling** + custom hook in `hatch_build.py` (runs
  `yarn build` into `cadquery_web_viewer/frontend` unless skipped or prebuilt).
- Wheel includes prebuilt `cadquery_web_viewer/frontend` when present.
- **Single source of version truth:** `package.json` is authoritative; the
  Hatchling hook reads it and injects the version into the wheel metadata.

## Common pitfalls

1. **Forgetting the two-step remote workflow** — `PUT` then `POST /api/events`.
2. **Editing `cadquery_web_viewer/frontend/` directly** — change `frontend/`
   and run `yarn build`.
3. **Breaking Three.js sharing** — do not add a second unresolved `three` copy;
   keep Vite `dedupe`.
4. **Assuming CadQuery is installed** — examples may use `cadquery`; the library
   depends on `build123d`.
5. **Yarn version** — Yarn 4 (Berry) via Corepack with the `node-modules`
   linker; use `yarn install --immutable`, **not** `--frozen-lockfile`.
