# Contributing to cadquery-web-viewer

Thanks for taking the time to contribute! This document covers the dev loop, the
checks you should run before opening a pull request, and the conventions the
existing code follows.

If you only want to file a bug or feature request, jump to the
[issue tracker](https://github.com/jimcortez/cadquery-web-viewer/issues) and use
one of the issue templates.

## Project layout

| Path | Role |
|------|------|
| `cadquery_web_viewer/` | Python package: Flask app, tessellation, GLB I/O, `show()` engine, HTTP client for remote mode |
| `cadquery_web_viewer/frontend/` | **Built** static UI bundled into the wheel (produced by `yarn build`, **not edited by hand**) |
| `frontend/` | **Source** Vue 3 + TypeScript UI (Vite entry: `frontend/index.ts`, root `index.html`) |
| `dist/` | Vite output when developing backend-only (`yarn build` at repo root) |
| `docs/` | User and API docs (`install.md`, `usage.md`, `api.md`, `development.md`, `yacv_migration.md`) |
| `examples/in-process/`, `examples/remote/` | Sample `show()` usage |
| `tests/` | Python `unittest` tests (Flask test client) |
| `assets/licenses.txt` | Third-party JS licenses (regenerated by `yarn update-licenses` during build) |

The frontend has two homes for a reason: edit `frontend/`, then `yarn build`
copies the bundle into `cadquery_web_viewer/frontend/` so the wheel ships a
prebuilt UI. Never hand-edit `cadquery_web_viewer/frontend/`.

## Development setup

**Requirements:** Python **3.10–3.13**, Node.js LTS, and Yarn (managed via
[Corepack](https://nodejs.org/api/corepack.html)).

```bash
# Python deps (preferred via uv)
uv sync                    # or: pip install -e ".[dev]"

# JavaScript deps
corepack enable
yarn install               # full install; needed for yarn build
```

Do **not** set `NODE_ENV=production` for `yarn install` before `yarn build` —
devDependencies (e.g. `generate-license-file`) are required.

### Two-terminal UI workflow

```bash
# Terminal 1 — Flask API (default http://localhost:32323)
uv run cadquery-web-viewer

# Terminal 2 — Vite dev server (often http://localhost:5173)
yarn dev
```

Vite dev proxies API calls: same-origin `/api/events` when possible; otherwise
falls back to `http://localhost:32323`. Details:
[docs/development.md](docs/development.md).

### Backend-only with a built UI

```bash
yarn build                 # writes repo-root dist/
uv run cadquery-web-viewer # serves dist/ if packaged frontend/ is absent
```

## Commands you should know

| Task | Command |
|------|---------|
| Run API server | `uv run cadquery-web-viewer` or `python -m cadquery_web_viewer` |
| Frontend dev | `yarn dev` |
| Production UI build | `yarn build` (runs license update, `vue-tsc`, Vite) |
| Frontend type-check | `yarn type-check` |
| Python lint | `uv run ruff check cadquery_web_viewer hatch_build.py` |
| Python typecheck | `uv run pyright` |
| Python tests | `uv run python -m unittest discover -s tests -v` |
| Wheel build (CI style, skip UI build) | `CADQUERY_WEB_VIEWER_SKIP_FRONTEND_BUILD=true uv build` |

CI (`.github/workflows/ci.yml`) runs the reusable build (`yarn build`,
`uv build` with skip flag, Docker image validation) and the test job
(`ruff`, `pyright`, `python -m unittest`, `yarn type-check`).

## Pull request expectations

Before opening a PR, please run the four quality gates locally:

```bash
uv run ruff check cadquery_web_viewer hatch_build.py
uv run pyright
uv run python -m unittest discover -s tests -v
yarn type-check
```

PRs that touch the HTTP API should update [docs/api.md](docs/api.md). PRs that
add or remove user-visible behavior should add a line to
[CHANGELOG.md](CHANGELOG.md) under the *Unreleased* heading.

Branches: feature branches off `main`. Use a short kebab-case description
(`fix-disk-hydrate-crash`, `add-export-csv`). The release workflow rebuilds and
publishes from `main` when a tag matching `v**` is pushed.

## Coding conventions

### Python

- Target **3.10+** syntax; line length **120** (Ruff).
- Ruff selects: `E4`, `E7`, `E9`, `F`, `I` — run before submitting.
- Pyright is configured with relaxed reporting in `pyproject.toml`; still match
  existing types and patterns in `cadquery_web_viewer/`.
- **Runtime dependency:** `build123d` (tessellation). **CadQuery** is *not* a
  package dependency; users install it separately for CadQuery examples.
- Prefer extending `CadQueryWebViewer` / Flask blueprints in `app.py` rather
  than duplicating store or event logic.

### TypeScript / Vue

- Use **Composition API** with `<script setup lang="ts">`.
- Put reusable logic in `frontend/composables/`; keep components focused.
- `model-viewer` is a **custom element** (configured in `vite.config.ts`).
- After changing `package.json` dependencies, `yarn build` refreshes
  `assets/licenses.txt` — commit that file when deps change.

### Tests

- Tests live in `tests/` and use **`unittest`** (stdlib), not pytest.
- Pattern: `create_app(cache_mode="memory")` + Flask `test_client()`; mock
  external HTTP with `unittest.mock.patch`.
- Add tests for new `/api/*` behavior, especially validation and status codes
  documented in [docs/api.md](docs/api.md).

## Reporting security issues

Please do **not** open a public issue for security problems. See
[SECURITY.md](SECURITY.md) for the private disclosure path.
